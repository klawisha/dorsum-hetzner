# Dorsum 2.1.0 — безопасность, функции и проверки
Дата: 20 октября 2026.

## Исходная версия
Основа — последний найденный полный архив Dorsum_stable_2.0.16-tablet-modal-actual-fix.zip.
Общедоступная ссылка на чат показывает более ранний фрагмент. В доступной истории не найдены подтверждённые требования после 2.0.16.
Проверены реальные исходники и поздние заметки, включённые в архив.

Сохранены:
- адаптивность календаря и редактора занятия, мобильные отступы и исправленный значок оплаты;
- перенос любого SCHEDULED, включая просроченное, с новым слотом в будущем;
- переход разовая услуга ↔ курс и между курсами;
- старые курсы с половинной/полной оплатой без фиктивной исторической выручки;
- отдельные семейные карточки на одном телефоне;
- группы с одинаковыми услугой и временем, серверным лимитом участников;
- окна отсутствия специалиста, скидки, касса по датам фактических платежей.

Общий телефон сохраняет прежнее правило: при нескольких активных клиентах клиентский вход отключён, администратор работает с отдельными карточками.
У каждого ребёнка собственные ClientProfile и курсы. Списание курса другого ребёнка запрещено.
Точные цены новых детских курсов не обнаружены — добавлен шаблон, фактические суммы задаёт центр.
Существующие лимиты групп в БД не заменяются предположениями.

SQL остаётся параметризованным; RawUnsafe API, eval и dangerouslySetInnerHTML не используются.
Сервер не принимает внешние URL для получения файлов и не выдаёт произвольные файлы файловой системы.
Добавлены CSP, запрет встраивания, nosniff, no-store/CDN-no-store и точный CORS.
Логи не содержат паролей, токенов, фотографий, заметок и строки БД.
Аудит действий содержит ID, маршрут, код ответа и requestId; доступ только ADMIN.

Это аудит найденных путей и исправление воспроизводимых рисков. Одной проверкой невозможно исключить все будущие уязвимости.

## Прайс, зарплаты и финансы
Новый экран ADMIN → Прайс / Выплаты:
- добавить услугу, курс, детский курс;
- цена, длительность, число занятий, аудитория;
- фиксированная сумма или процент после скидки;
- массажная сетка и гарантированный минимум;
- групповой режим, лимит, выплата за участника или один раз за сеанс;
- архивирование/возврат услуги с сохранением истории;
- новая версия массажной сетки с будущего месяца.

Разовая запись сохраняет цену и ставку при создании.
Проданный курс сохраняет цену, число занятий и правила начисления при продаже.
Процент курса: полная цена после скидки / число занятий × процент.
Для общей групповой выплаты ставка и правила берутся из первой записи сеанса и учитываются один раз.
Динамическая массажная ставка зависит от нагрузки за соответствующий месяц, версии сетки и сохранённых правил записи.
При изменении прайса прежние записи и проданные курсы не переписываются.

Публичный сайт получает цены из этого же каталога. Вручную прописанные цены удалены.
Каталог обновляется при открытии, возвращении на страницу и каждые 30 секунд в активной вкладке.

Касса учитывает фактические платежи, каждую половину курса в дату оплаты, продажи инвентаря и возвраты.
Занятие по курсу не создаёт повторную выручку.
Зарплата — только COMPLETED, отдельно от кассового потока.
Суммы округляются до копеек; существующий Float БД сохранён для совместимого переноса.
Неиспользованный курс отменяется с сохранением исходной продажи и отрицательным REFUND на текущую дату.
Реальный возврат денег выполняет администратор отдельно: платёжная интеграция для автоматического возврата не добавлялась.

Проверенный финансовый пример:
разовые 500 + 900 = 1400; курс 2000; касса 3400;
выплаты 100 + 250 + 150 = 500; расходы 100; остаток 2800 грн.
Тест включает изменение прайса между продажами, чтобы проверить сохранение старых сумм.

## Фото
Хранение PostgreSQL bytea сохранено: ClientCardImage и ExpenseReceipt.
Дамп БД переносит изображения вместе с остальными данными.
Новые файлы: до 5 МБ, до 25 млн пикселей, полное декодирование JPEG/PNG/WebP, удаление EXIF/GPS и перекодирование WebP.
Файлы шифруются отдельным MEDIA_ENCRYPTION_KEY с AES-256-GCM и AAD по записи.
Старые файлы шифруются отдельной миграцией с проверкой сохранения исходных байтов.
Backup всего дампа дополнительно шифруется age.
Восстановление требует БД и прежнего MEDIA_ENCRYPTION_KEY.
Копия на диске того же VPS не заменяет внешний backup.

## Проверки и границы подтверждения
Проведены:
- модульные проверки конфигурации, паролей, валидации, шифрования, изображений, часового пояса;
- интеграционные HTTP-проверки доступа, JWT, сессий, CSRF, фото, групп, семей, курсов, прайса, зарплат, кассы, возвратов и brute force;
- все 23 миграции с пустой БД;
- обновление отдельной базы с 20 миграций stable 2.0.16: сохранены количества, деньги, остатки, выплаты и отпечатки изображений;
- Chromium на 320, 375, 390, 768, 1024 и 1440 пикселях;
- страницы прайса, курсов, клиентов, финансов, календаря, публичного сайта; форма детского курса и редактор занятия;
- ошибки JavaScript, горизонтальное переполнение, выход полей за границы редактора;
- ESLint и production build;
- синтаксис shell/Python, структура Compose, генератор конфигурации и режимы доступа;
- npm audit обеих частей.

Подробные фактические результаты — в docs/verification.
В этой среде интеграционные проверки выполнены на PostgreSQL WASM (PGlite).
Две проверки настоящей конкурентности выполняются отдельным CI с PostgreSQL 18.
Docker daemon, реальные аккаунты, production-БД, DNS и VPS здесь недоступны.
Сборка контейнера, Caddy validate и проверка runtime-роли включены в CI.
Реальные pg_dump/restore, внешняя загрузка backup, домены и физические Android/iPhone проверяются по инструкции после установки.
Внутренние браузерные скриншоты в архив не включены.

## Эксплуатация
Не использовать migrate reset, docker compose down -v или удаление данных PostgreSQL.
Не менять MEDIA_ENCRYPTION_KEY при обновлении.
Перед переключением сверить импорт, пройти CI, включить backup и проверить восстановление.
Не держать два backend с независимыми БД доступными для записей одновременно.
Старые пароли БД, попадавшие в Render-логи, сменить/отозвать при завершении переноса.
Секреты и ключи хранить отдельно от исходников.
